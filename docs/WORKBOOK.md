## Mom Test 요약

| 항목 | 내용 |
|------|------|
| **페르소나** | 길이 단위 변환이 필요할 때 **계산기**를 가장 자주 쓰는 사용자. 단위 **이름**을 헷갈리기 쉬움 (예: mm ↔ m). |
| **진짜 문제 (한 문장)** | 계산기로 단위를 바꿀 때 단위 이름을 헷갈려 잘못 입력하면, 결과가 이상하게 나온 뒤에야 틀렸다는 걸 알고 다시 확인·재계산해야 한다. |
| **Mom Test 증거 3줄** | ① 「계산기를 가장 많이 사용해」 ② 「단위 이름」 때문에 헷갈린다 ③ 「mm를 m로 잘못 작성」한 적이 있고, 「단위 변환이 너무 작아서 이상하다고 생각했」다 |

## 1) 주제 한 문장

> **단위 이름을 명확히 넣었을 때만 변환하고, 틀리면 결과가 나오기 전에 바로 알 수 있게 한다.**

- Mom Test의 **불편**(이름 헷갈림 → 잘못된 결과 → 뒤늦은 재확인)을 겨냥한다.
- 「프로그램을 만든다」가 아니라 **판정 시점을 앞당기는 것**이 주제다.

## 2) R-G-I-O

| | 내용 |
|---|------|
| **Role** | 길이 단위 변환이 필요한 사용자(계산기 의존, 단위 이름 혼동 경험 있음)를 대신해 **입력 검증과 일괄 변환 결과**를 제공하는 CLI를 만드는 프로그래머 |
| **Goal** | 단위 이름 오입력·미등록 단위를 **변환 전에 거부**하고, 올바른 입력에 대해서는 **등록된 모든 단위로 한 번에 환산**해 사용자가 결과를 바로 대조·판정할 수 있게 한다 |
| **Input** | `단위이름:숫자` 형식 문자열 (예: `meter:2.5`). CLI 옵션: `--format`, `--config` (P1) |
| **Output** | 소스 단위·값 대비 **다른 등록 단위 전체**의 환산 결과. 기본 table, 선택 시 json/csv. 오류 시 **명확한 메시지**(형식 오류·음수·미등록 단위) |

### R-G-I-O ↔ Mom Test 연결

```
[Mom Test 불편]  단위 이름 헷갈림 → 잘못된 계산 → "이상하다"고 뒤늦게 발견
       ↓
[Goal]           입력 단계에서 이름·형식 검증 → 이상한 결과 대신 즉시 오류
       ↓
[Output]         한 번에 모든 단위 결과 → 대조로 "너무 작다" 같은 이상 징후 조기 발견
```

## 3) 성공 기준 3개

| # | 성공 기준 | Mom Test 증거 연결 | 검증 방법 (TDD 예고) |
|---|-----------|-------------------|----------------------|
| **SC-01** | 미등록·잘못된 단위 이름 입력 시 변환 결과 없이 **즉시 오류**가 난다 | ③ mm/m 혼동처럼 **잘못된 이름**이 들어왔을 때, 이상한 숫자가 나오지 않아야 함 | `cubit:1` → `UnknownUnitError` (FR-03) |
| **SC-02** | 입력 형식이 `단위:값`이 아니거나 음수이면 **거부**된다 | ② 단위 **이름**과 값이 분리·검증되어 헷갈린 입력이 그대로 통과하지 않음 | `meter / abc`, `meter:-1` (FR-04, FR-05) |
| **SC-03** | 올바른 입력 한 번으로 **모든 등록 단위** 결과가 나와 **대조·판정**이 가능하다 | ③ 「너무 작아서 이상하다」— 여러 단위 결과를 한눈에 보고 이상 여부를 빨리 판단 | `meter:2.5` → feet, yard 등 전체 출력 (FR-02) |

## 4) 표면 문제 — 이번 프로젝트에서 하지 않을 것

| 표면 문제 (잘못된 정의) | 하지 않는 이유 |
|-------------------------|----------------|
| 「길이 단위 변환 **프로그램을 만든다**」 | 기능 나열이지 사용자 불편(이름 혼동 → 늦은 발견)을 해결하지 않음 |
| 범용 **계산기** 대체 | Mom Test: 계산기는 쓰지만, 문제는 계산 자체가 아니라 **단위 이름 판정** |
| **GUI·모바일 앱** | 이번 세션 범위 밖; CLI로 입력 검증·일괄 출력에 집중 |
| **질량·온도 등** 다른 물리량 | PRD 범위 = 길이 단위만 (meter, feet, yard + 확장) |
| mm·inch 등 **PRD/TDD 범위 밖** 단위 선구현 | P1 확장(Registry/OCP)으로 열어두되, P0 성공 기준과 무관한 선행 작업 금지 |
| 「만들면 좋겠다」식 **부가 기능** (히스토리, 즐겨찾기, AI 추천 등) | Mom Test 증거에 없음 |

### Rule — 지켜야 할 규칙

**도메인 규칙**

| ID | 규칙 |
|----|------|
| R-01 | 입력은 반드시 `단위이름:숫자` 한 쌍이다. |
| R-02 | 값은 0 이상이어야 한다. 음수는 거부한다. |
| R-03 | 단위는 Registry에 등록된 이름만 허용한다. 미등록 시 거부한다. |
| R-04 | 환산은 **meter를 허브**로 한다. feet ↔ yard 등도 meter 경유. |
| R-05 | 기본 단위: meter(1.0), feet(0.3048), yard(0.9144). |

**설계 규칙 (NFR)**

| ID | 규칙 |
|----|------|
| R-06 | **SRP**: Parser / Registry / Converter / Printer 는 각자 한 가지 책임만 갖는다. |
| R-07 | **OCP**: 새 단위·출력 포맷 추가 시 Converter 핵심 로직을 수정하지 않는다. |
| R-08 | 오류 메시지는 **원인**(형식·음수·미등록 단위)을 구분해 사용자가 이름을 고칠 수 있게 한다. |

**개발 규칙 (이번 세션)**

| ID | 규칙 |
|----|------|
| R-09 | 구현 전 **실패하는 테스트**를 먼저 쓴다 (RED). |
| R-10 | 테스트 통과에 필요한 **최소 코드**만 쓴다 (GREEN). |
| R-11 | 통과 후 구조만 정리한다 (REFACTOR). 기존 테스트는 깨지지 않아야 한다. |

### Command — 실행·작업 명령

**사용자 CLI (목표 인터페이스)**

```bash
# 기본 변환 (table 출력)
python -m unit_converter "meter:2.5"

# 출력 형식 (P1)
python -m unit_converter "meter:2.5" --format json
python -m unit_converter "meter:2.5" --format csv

# 외부 단위 정의 (P1)
python -m unit_converter "meter:2.5" --config path/to/units.json
```

**개발자 명령 (Test Loop용)**

```bash
# 테스트 실행 (전체)
pytest

# 테스트 실행 (모듈별 — ARRR 1사이클 단위)
pytest tests/test_parser.py -v
pytest tests/test_registry.py -v
pytest tests/test_converter.py -v

# 패키지 직접 실행 (구현 후)
python -m unit_converter "meter:2.5"
```

|-------|------|

| **불편 우선** | SC-01(즉시 오류) → SC-02(입력 거부) → SC-03(일괄 대조) 순으로 사이클을 잡는다. |
