## 1. Executive Summary

길이 단위 변환이 필요한 사용자는 계산기를 자주 사용하지만, **단위 이름을 헷갈려 잘못 입력**하는 경우가 있다. 잘못된 입력은 이상한 결과를 낳고, 사용자는 결과가 「너무 작다」 등으로 이상하다고 느낀 **뒤에야** 오류를 발견해 재확인·재계산한다.

본 프로젝트의 주제는 「변환 프로그램을 만드는 것」이 아니라, **단위 이름을 명확히 넣었을 때만 변환하고, 틀리면 결과가 나오기 전에 바로 알 수 있게 하는 것**이다.

---

## 2. Mom Test 결과

### 2.1 페르소나

길이 단위 변환이 필요할 때 **계산기**를 가장 자주 쓰는 사용자. 단위 **이름**을 헷갈리기 쉬움 (예: mm ↔ m).

### 2.2 표면 문제 (잘못된 정의)

> 「길이 단위 변환 프로그램을 만든다」

기능 나열에 그치며, 사용자가 겪는 **불편·판정 지연**을 설명하지 못한다.

### 2.3 진짜 문제 (한 문장)

> 계산기로 단위를 바꿀 때 단위 이름을 헷갈려 잘못 입력하면, 결과가 이상하게 나온 뒤에야 틀렸다는 걸 알고 다시 확인·재계산해야 한다.

### 2.4 Mom Test 증거

| # | 인용 (사용자 발언) |
|---|-------------------|
| ① | 「계산기를 가장 많이 사용해」 |
| ② | 「단위 이름」 때문에 헷갈린다 |
| ③ | 「mm를 m로 잘못 작성」한 적이 있고, 「단위 변환이 너무 작아서 이상하다고 생각했」다 |

### 2.5 인터뷰 맥락 요약

| 질문 영역 | 발견 |
|-----------|------|
| 현재 행동 | 계산기 사용이 가장 빈번 |
| 불편 지점 | 변환 단위(이름) 헷갈림 |
| 구체적 혼동 | 단위 **이름** (환산 숫자·곱셈 방향이 아님) |
| 실제 사례 | mm를 m로 잘못 작성 |
| 발견 시점 | 결과가 너무 작아 이상하다고 **느낀 후** |
| 비용 | 재확인·재계산 (시간·주의력 소모) |

---

## 3. 주제 한 문장

> **단위 이름을 명확히 넣었을 때만 변환하고, 틀리면 결과가 나오기 전에 바로 알 수 있게 한다.**

- **겨냥하는 불편:** 이름 헷갈림 → 잘못된 결과 → 뒤늦은 재확인
- **핵심 가치:** 판정 시점을 **앞당김** (결과 이상 징후에 의존하지 않음)

---

## 4. R-G-I-O

| | 정의 |
|---|------|
| **Role** | 길이 단위 변환이 필요한 사용자(계산기 의존, 단위 이름 혼동 경험 있음)를 대신해 **입력 검증과 일괄 변환 결과**를 제공하는 CLI를 만드는 프로그래머 |
| **Goal** | 단위 이름 오입력·미등록 단위를 **변환 전에 거부**하고, 올바른 입력에 대해서는 **등록된 모든 단위로 한 번에 환산**해 사용자가 결과를 바로 대조·판정할 수 있게 한다 |
| **Input** | `단위이름:숫자` 형식 문자열 (예: `meter:2.5`). CLI 옵션: `--format`, `--config` (P1) |
| **Output** | 소스 단위·값 대비 **다른 등록 단위 전체**의 환산 결과. 기본 table, 선택 시 json/csv. 오류 시 **명확한 메시지**(형식 오류·음수·미등록 단위) |

### 4.1 Mom Test → R-G-I-O 연결

```
[불편]   단위 이름 헷갈림 → 잘못된 계산 → "이상하다"고 뒤늦게 발견
   ↓
[Goal]   입력 단계에서 이름·형식 검증 → 이상한 결과 대신 즉시 오류
   ↓
[Output] 한 번에 모든 단위 결과 → 대조로 이상 징후 조기 발견
```
